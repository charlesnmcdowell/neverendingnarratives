### 🐞 NEW — `dual-form-lich-archfiend` (P3 logic / spec-divergence — game3d main.js, NOT live)

**What's wrong:** the warlock can end up with BOTH `this.lich` and `this.archfiend` true at once — two mutually-exclusive lv20 ascension forms layered on the same actor. The horde then scales as ARCHFIEND (`hordeMul()` reads `evo20==='archfiend'` → ×ARCHFIEND_DMG dmg + wider AoE) while the light attack routes to the LICH SCYTHE (`update()` L1346 `this.lich ? lichSlash : (inDevil()? devilClaw : melee)` — lich wins), the HUD reads `[LICH]`, and `tickUpkeep`'s phylactery can later `lichPerish()` mid-fight and silently drop the player to the devil-claw form. Inconsistent, off-spec state (each road is supposed to terminate in exactly one form).

**5-Whys:**
1. Why dual form? `pickEvo(20)` runs `enterArchfiend()` with no guard against an already-active `this.lich`.
2. Why is lich already active at the lv20 pick? `archDevilOutro()` (lv8 timed-devil expiry) calls `enterLich()` on the BASE/no-road branch — a *guaranteed* cast-down Lich (intended per run #43) — but it can fire **before** the lv10 road is ever chosen.
3. Why before the road pick? Leveling is `floor(1+1.5·kills)`: lv8 (DEVIL_LV, borrow-eligible) lands at **5 kills**, lv10 (road card) at **6**. If the player presses K at lv8 to summon (→`enterDevil()` borrow, 15s) and the borrow EXPIRES before they get the 6th kill, `archDevilOutro` runs with `this.road===null` → base branch → `enterLich()`.
4. Why does that allow a herald-archfiend later? With `road` still null at the outro, the lv10 card still opens (`tickProgression`: `lvl>=10 && !this.road`), the player can pick **HEX FIEND (herald)**, then at lv20 the filtered ascension offers **archfiend** → `enterArchfiend()` while `lich` is still set.
5. Why no backstop? No invariant enforces "at most one terminal form"; `enterLich`/`enterArchfiend`/`enterDemonLord` each set their own flags without clearing/declining the others.

**Ishikawa (primary):** code-logic (missing single-form invariant + outro-before-road ordering). Not engine/asset/platform.

**Repro (headless / driver):** start warlock; reach lv8 (5 kills); press K (raises coven → lv8 timed ARCH DEVIL borrow); do NOT reach the 6th kill for ~15s so the borrow expires with `road===null` → `archDevilOutro` → `enterLich` (player is Lich, no road). Continue to lv10 → pick **HEX FIEND**; continue to lv20 → pick **ARCHFIEND ASCENDANT**. Observe `__AUDIT__.lich===true && __AUDIT__.archfiend===true` simultaneously.

**Suggested fix (game3d-build's call — design):** make terminal forms exclusive — e.g. `pickEvo(20)`/`enterArchfiend`/`enterDemonLord` early-return or clear `this.lich` when a form is already set; and/or gate `archDevilOutro`'s base→Lich cast-down so it doesn't pre-empt the lv10 road choice (defer the outro until a road exists, or have the no-road outro just `exitDevil()`).

**Severity P3:** no crash / no softlock / progression NOT blocked (waves still clear, sim runs) — a state/spec inconsistency only. game3d is NOT live → not shipped; not auto-fixed (build-owned combat design).
